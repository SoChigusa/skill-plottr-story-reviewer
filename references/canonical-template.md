# Plottr連作長編プロジェクトテンプレート

## 0. この文書の位置づけ

この文書は、次の形式の小説をPlottrで設計するための共通仕様である。

- 一冊：約8万～12万字
- 各話：約8,000～12,000字
- 話数：おおむね8～12話
- 各話：局所的な問題と決着を持ち、単独でも一定の満足を与える
- 全体：一つの貫通行動、人物変化、情報開示、テーマを持つ
- 最終部：それまでの各話を再解釈させる大きな真相または結末を置く

このファイルをChatGPTプロジェクトの参照ファイルとして追加した場合、AIは本書の対応関係、命名規則、変更手順を基準として提案すること。

全体幕の起承転結には、本プロジェクトで採用する「シナリオ・センター式」を用いる。本書における同方式の定義は、ユーザーが読書資料から要約して提示した次の原則を正本化したものである。

- `起`：天地人、物語のジャンルとテイストを提示し、アンチテーゼから始める。
- `承`：主人公へ障害をぶつけ、困らせ、葛藤させることで、起から転までをつなぐ。
- `転`：テーマを伝える。
- `結`：テーマを定着させ、余韻を残す。
- 書きやすい目安は、本文量で`起：承：転：結 = 1：5：1：1未満`とする。

全体幕の判定では、出来事の大きさや一般的な「転換点」という呼称よりも、上記の**機能**を優先する。詳細は第4節に定める。

重要原則は次の一文に集約される。

> 各話は局所的には閉じるが、全体状況には不可逆な差分を残す。

## 1. Plottrと作品構造の対応

| Plottrの機能 | 本テンプレートで担当させるもの | 典型的な規模 |
|---|---|---:|
| Project | 作品世界、シリーズ、関連作品、別バージョンの容器 | 単巻より上 |
| Book | 今回執筆する文庫本一冊 | 約10万字 |
| Series View | 複数巻をまたぐ出来事や伏線 | 複数巻 |
| 最上位構造 | 全体幕（全体の起・承・転・結） | `1：5：1：1未満`を目安に機能配分 |
| 中間構造 | E01～最終話 | 約1万字／話 |
| 最下位構造 | 場面または主要ビート | 約1,000～2,000字程度 |
| Plotline | 全編を横断して追跡する物語上の線 | 横断軸 |
| Scene Card | 特定場面における出来事、判断、情報、状態変化 | 一機能・一変化 |
| Custom Attribute | Scene Cardの定型記入欄 | 項目単位 |
| Tag | 複数場面を横断して検索する短い印 | 横断分類 |
| Note | 全体設計、各話設計、真相、設定などの長文資料 | 設計書 |
| Character / Place | 人物・場所のマスターデータ | 設定資料 |
| Outline | Timelineを物語順・文章順に点検する表示 | 点検・出力 |

### 採用しない対応

- 各話を別々のBookにはしない。全話を一本のTimelineで俯瞰できなくなるため。
- 第1話、第2話などをPlotlineにはしない。話数は時間軸上の容器であり、横断軸ではないため。
- 単巻だけを設計する段階ではSeries Viewを主設計に使わない。BookのTimelineと二重管理になるため。
- Scene Card一枚を必ず一つの実景として扱わない。同じ実景について、複数のPlotlineに機能別カードを置ける。

## 2. 推奨階層

八話前後で、一話をおおむね同程度の長さにする場合の基本形を示す。

```text
Project：作品世界／シリーズ
└── Book：今回の一冊
    ├── 全体幕「起」
    │   └── E01 第1話
    │       ├── E01-S01 導入
    │       ├── E01-S02 事件発生
    │       └── ……
    ├── 全体幕「承」
    │   ├── E02 第2話
    │   ├── E03 第3話
    │   ├── E04 第4話
    │   ├── E05 第5話
    │   └── E06 第6話
    ├── 全体幕「転」
    │   └── E07 第7話
    └── 全体幕「結」
        └── E08 第8話（通常話より短くしてよい）
```

これは`起：承：転：結 = 1：5：1：1未満`をEpisode単位へ近似した基本形である。話数が8～12話のどこに収まる場合でも、比率はEpisode数ではなく**本文量と読者が受ける時間感覚**で判定する。

配分は絶対値ではないが、変更は「物語の転換点がどこか」ではなく、第4節の幕機能をどのEpisodeが担うかによって決める。決定的破綻や最低点が起きたというだけで、そのEpisodeを自動的に`転`へ入れてはならない。

## 3. Plottrの初期設定

### 3.1 ProjectとBook

1. Blank Projectを作成する。
2. Project名には作品名またはシリーズ名を付ける。
3. Bookは一冊だけ作り、今回の約10万字全体を入れる。
4. 続巻を実際に設計し始めるまではSeries Viewを使用しない。

### 3.2 Structure

Timeline上部のStructureから三層を作り、次のように改名する。

| 初期名称 | 使用名称 |
|---|---|
| Acts | 全体幕 |
| Chapters | 話 |
| Scenes | シーン |

新規プロジェクトに最初からある`Chapter 1`は、文学上の章として固定されたものではない。本テンプレートでは、三層化した後の最下位単位、すなわち`E01-S01`として扱う。

初期状態を次のように改名する。

```text
全体幕1 → 起
第1話    → E01｜第1話「仮題」
シーン1  → E01-S01｜導入
```

### 3.3 表示の使い分け

- Default：全編を頭から終わりまで並べて編集するとき。
- Tabbed：特定の全体幕だけに集中するとき。
- Stacked：全体幕、話、シーンの所属関係を確認するとき。
- Small Zoom：全編のカード密度や空白を俯瞰するとき。
- Outline：カードを物語順に読んで因果を点検するとき。

## 4. 全体幕の役割――シナリオ・センター式

### 4.1 正式定義

| 全体幕 | 本プロジェクトでの正式な機能 | 終了判定 |
|---|---|---|
| 起 | 天地人、物語のジャンルとテイストを提示し、テーマのアンチテーゼが支配する初期状態から始める | 読者が「どんな世界で、誰が、どんな調子の物語を生きるか」と、初期状態を支配する反命題を把握した |
| 承 | 主人公へ障害を連続してぶつけ、困らせ、選ばせ、葛藤させることで、起のアンチテーゼから転のテーマ提示までを因果でつなぐ | 主人公が従来の考え方・方法では進めない最低点または最終葛藤に達し、テーマ上の選択を迫られた |
| 転 | 作品のテーマを、主人公の認識、選択、行動、および主要問題の決着を通して伝える | 主人公が最終回答を選び、その回答に基づく行動で主要な外的問題を決着させた |
| 結 | 転で示したテーマが一時的な勝利ではなく、人物、関係、世界、日常へ定着したことを見せ、余韻を残す | 変化後の状態と感情的な着地を示し、新たな主要問題を開始せず閉じた |

### 4.2 用語の運用定義

- **天地人**：世界・時代・場所・社会法則などの「天」、主人公が置かれた具体的状況や物語の舞台となる「地」、主人公と主要人物、その初期関係・欲求・欠落である「人」を指す。
- **ジャンルとテイスト**：異世界ファンタジー、事件解決、バディもの、喜劇性、陰鬱さなど、読者が以後期待すべき物語体験を指す。説明文ではなく、実際の場面で示す。
- **アンチテーゼ**：最終テーマに反する価値観、またはそれが正しいように見える初期状態を指す。悪役の台詞だけでなく、世界の制度、主人公の逃避、周囲の常識、事件の不公正などによって具体化する。
- **テーマを伝える**：最終回答を説明することではない。主人公が反対命題と葛藤した末に最終回答を選び、その選択による行動がクライマックスと主要問題の決着を生むことを指す。
- **テーマの定着**：結で新たに答えを発見することではない。転で獲得・証明された答えが、その後の暮らし、関係、制度、反復される行動へ残っていることを示す。

### 4.3 配分の原則

書きやすい基本比率は、本文量で次のとおりとする。

```text
起：承：転：結 = 1：5：1：1未満
```

- `起`と`転`は、原則として各一単位前後へ圧縮する。
- `承`を最長とし、物語の進行、障害、葛藤、成功、誤答の強化、決定的破綻、最低点までを主に担わせる。
- `結`は通常Episodeより短くてよい。主要問題の解決を残してはならず、定着と余韻に専念させる。
- 比率は機能を明瞭にするための目安であり、機械的な字数合わせを目的としない。ただし大きく外れる場合は、幕機能が隣の幕へ流出していないかを必ず点検する。

### 4.4 幕境界を決める優先手順

全体幕を割り当てるときは、次の順で決める。

1. **転を決める。** 主人公が最終テーマを選び、その選択を決定的行動へ変え、主要問題を解決するEpisodeまたは区間を特定する。
2. **結を決める。** 主要問題解決後の変化した日常、関係、制度、感情的着地だけを残す短い区間を特定する。
3. **起を決める。** 天地人、ジャンルとテイスト、アンチテーゼを提示する最小限の冒頭区間を特定する。
4. **残りを承とする。** 起で示した状態から転のテーマ選択までを、障害と葛藤の因果でつなぐ。
5. 最後に`1：5：1：1未満`の比率を確認し、機能の流出があればSceneまたはEpisodeを再配分する。

### 4.5 判定上の禁止事項

- 「大きな事件が起きた」「前提が崩壊した」「主人公が最低点へ落ちた」という理由だけで、その位置を`転`と呼ばない。これらは本方式では通常、`承`終盤の機能になり得る。
- `転`を単なる意外な展開、真相開示、敵の勝利にしない。主人公がテーマ上の最終回答を選び、行動で示すことを必須とする。
- `結`で初めて最終回答を出さない。最終回答は`転`で伝え、`結`では定着させる。
- `結`へ救出、最終対決、主要制度の決定、主要謎の解明を持ち越さない。それらが残る場合、その区間はまだ`転`である。
- `起`を設定説明だけのEpisodeにしない。アンチテーゼが働く具体的事件と主人公の初期選択を含める。
- 比率だけを理由に、必要な因果や感情を削らない。機能を満たしたうえで圧縮する。

### 4.6 箱書きの操作原則――「困る／すごく困る」

シナリオ・センター式を本プロジェクトでEpisode解像度へ落とす際は、まず出来事を難しく説明せず、主人公が何に困らされる話なのかを一文で置く。

```text
承のEpisode：
【具体的な障害・事態】で、主人公が困る。

転のEpisode：
【承で育てた矛盾・最大級の障害】で、主人公がすごく困る。
```

この書式は、Episodeの箱を前へ進めるための簡易な作業言語として正式採用する。

#### 承の「困る」

- `承`では、各Episodeごとに主人公へ新しい障害をぶつける。
- 「困る」は、単なる不運ではなく、主人公に判断・選択・試行錯誤を要求する状態を指す。
- 各Episodeの困り方は変奏させる。対象、規模、利害、認識、方法、代償の少なくとも一つを前話から変える。
- 解決して元通りにするだけではなく、その解決方法・成功・代償が次のEpisodeの困り事の原因になることを優先する。
- 特に承後半では、主人公がうまくなり成功するほど、誤答・奢り・代償も育つ構造を推奨する。
- `PL-03｜各話の局所問題`のEpisodeカードには、まず「〜で、主人公が困る」と書き、その下に解決主軸と留保を書く方法を標準とする。

#### 転の「すごく困る」

- `転`では、承で積み上げた方法、信念、関係、誤答のすべてをまとめて試す最大級の問題を主人公へぶつける。
- 「すごく困る」は、敵が強い、被害が大きいという外的スケールだけを意味しない。
- 主人公が、従来の方法では解けず、テーマ上の最終回答を選ばなければ前へ進めない状態であることを必須とする。
- したがって、転の箱書きは「すごく困る」で止めず、Scene設計では必ず次の因果へ展開する。

```text
最大の困難
→ 従来の方法／誤答では解けない
→ テーマ上の最終回答を選ぶ
→ その回答に基づく新しい行動
→ 主要問題の決着
```

- 少女の誘拐、最終対決、破滅の危機などは、「すごく困る」ための外的圧力になり得るが、それだけでは`転`の機能を満たさない。
- `PL-03`では外的な「すごく困る」を短く記し、`PL-04`で内的葛藤、`PL-06`で認識反転、`PL-07`で最終回答を分担して記録する。

#### 箱書き点検

承と転のEpisodeカードだけを縦に読んだとき、次のように読めることを確認する。

```text
〜で主人公が困る。
→ その解決の結果、次は〜で主人公が困る。
→ ……
→ 承で積み上げたものが裏返り、〜で主人公がすごく困る。
→ テーマ上の答えを選ぶことで、初めて解決できる。
```

「困る」の内容が前話と同じ、前話の結果と因果でつながらない、または転の「すごく困る」が単なる規模拡大に留まる場合は、箱書きを再検討する。

全体幕は原則として容器として使う。重要情報を全体幕そのもののカードだけに書かず、Notesまたは該当Sceneのカードにも記録する。

## 5. 各話の役割

各話は、必ず次の二つを同時に持つ。

1. 局所的完結：その話で提示された主要な問いに答える。
2. 全体差分：人物、関係、目的、情報、世界のいずれかを元に戻せない形で変える。

各話の終了時には、次の式を満たしているか確認する。

```text
各話の読後感
= 局所問題への回答
+ 主人公が支払った代償
+ 全体状況の不可逆な変化
+ 次に残る未解決事項
```

### 八話構成の初期配分例

| 話 | 全体幕 | 全体上の役割 |
|---:|---|---|
| E01 | 起 | 天地人、ジャンルとテイスト、アンチテーゼを事件の中で提示し、物語を起動する |
| E02 | 承1 | 最初の障害へ取り組ませ、主人公の方法または暫定回答を成功させる |
| E03 | 承2 | 対象・規模・条件を変え、同じ方法では処理できない障害をぶつける |
| E04 | 承3 | 成功を拡張し、代償、編集権、誤解、対抗命題への接近を生む |
| E05 | 承4 | 大きな偽の成功を与え、主人公の誤答をもっともらしく強化する |
| E06 | 承5 | 偽の成功を破綻させ、過去と現在の葛藤を収束し、最低点と転への契機を置く |
| E07 | 転 | 最終テーマを選択と行動で伝え、クライマックスを経て主要問題を決着させる |
| E08 | 結 | 変化後の日常・関係・世界を短く示し、テーマを定着させて余韻を残す |

八話以外では、この機能列を保持したまま`承`の変奏数を増減する。十話構成だからといって、旧来の`起2話／承3話／転3話／結2話`へ自動配分しない。

## 6. 標準Plotline

最初は次の七本を作る。必要が生じるまで増やさない。

| ID | Plotline名 | 記録する内容 | カードを置く条件 |
|---|---|---|---|
| PL-01 | 表の事件 | 読者が実際に読む主要な出来事 | 原則として全Scene |
| PL-02 | 貫通行動 | 主人公の全編目標への接近、後退、代償 | 距離・方針・代償が変化したとき |
| PL-03 | 各話の局所問題 | その話固有の目的、障害、決着 | 局所問題が動いたとき |
| PL-04 | 主人公の内的変化 | 信念、感情、関係、自己認識の変化 | 開始時と終了時で状態が変わるとき |
| PL-05 | 読者への情報 | 伏線、強化、誤誘導、部分開示、回収 | 読者の理解を操作したとき |
| PL-06 | 登場人物の認識 | 主人公や主要人物が知ること、誤解すること | 人物の認識が変わるとき |
| PL-07 | テーマ | アンチテーゼ、暫定回答、対抗命題、転での最終回答、結での定着 | 価値判断またはその位置づけが変化したとき |

### PL-07と全体幕の対応

- `起`：冒頭でアンチテーゼを示すカードを置き、必要なら起の終端に最初の亀裂または暫定回答を置く。
- `承`：主人公の暫定回答、成功による誤信、対抗命題への接近、最低点での誤答を追跡する。同じ主張を反復せず、障害によって回答を変化させる。
- `転`：最終回答を主人公の選択とクライマックス上の行動へ結びつける。テーマの最終回答を初めて確定する中心位置とする。
- `結`：転で確定した最終回答が日常・関係・制度へ残ったことを示す。新しいテーマ回答を追加しない。

カードタイトルには、出来事の要約ではなく、そのSceneで有効になった価値判断を書く。必要に応じて`[T01:反命題]`、`[T01:暫定回答]`、`[T01:誤答]`、`[T01:最終回答]`、`[T01:定着]`のように段階を明記する。

### Scene Cardの基本原則

- `PL-01 表の事件`には、原則として各Sceneに一枚以上置く。
- その他のPlotlineには、状態が変化したSceneだけカードを置く。
- カードがないことは「その線が動かなかった」という情報になる。
- 同じ出来事を文章ごと複製しない。それぞれのPlotlineで果たす機能だけを書く。
- 一枚のカードには、原則として一つの判断、一つの開示、一つの変化を書く。

### 同一Sceneの記入例

Scene：`E01-S03｜証拠写真を見て依頼を受ける`

| Plotline | Scene Card |
|---|---|
| 表の事件 | 写真に失踪者を見つけ、主人公は依頼を受ける |
| 貫通行動 | 全体の謎と同じ紋章が写っている |
| 主人公の内的変化 | 他人に関わらないという方針を破る |
| 読者への情報 | 写真の隅に赤い傘を置く。F03・種 |
| 登場人物の認識 | 主人公は赤い傘を偶然だと思う |

## 16. 段階的な作成手順

### Phase 1：最大解像度

1. 一文要約を作る。
2. テーマを問いとして作る。
3. 貫通行動を動詞で定義する。
4. 最終真相を作者用の客観文で書く。
5. 主人公と読者に信じさせる偽の全体像を決める。

### Phase 2：Episode解像度

1. 転で主人公が選ぶ最終回答、決定的行動、主要問題の決着を先に定義する。
2. 結で示す変化後の日常、関係、制度、余韻を定義する。
3. 起で提示する天地人、ジャンルとテイスト、アンチテーゼを定義する。
4. 起から転までをつなぐ承の障害、成功、葛藤、誤答、最低点を段階化する。
5. E01以降のEpisodeを並べ、各話の局所問題と決着を一文ずつ書く。
6. 各話終了時の不可逆な差分を書く。
7. 第4節の正式定義に従って各話を全体幕へ割り当てる。
8. 本文量が概ね`1：5：1：1未満`になっているか確認する。
9. 同じ役割のEpisodeが連続していないか、特に承が単なる成功例の反復になっていないか確認する。

### Phase 3：仮Scene解像度

各話にまず四つの仮Sceneを置く。

```text
E01-S01｜起
E01-S02｜承
E01-S03｜転
E01-S04｜結
```

この時点では細部を書き込みすぎない。

### Phase 4：実Scene解像度

四つの仮Sceneを、必要に応じて6～10Sceneへ分割する。

```text
起 → フック／事件発生
承 → 第一試行／悪化／代償
転 → 認識反転／方針転換
結 → クライマックス／局所的決着／全体へのフック
```

### Phase 5：横断線

1. PL-01表の事件を全Sceneに置く。
2. 貫通行動の変化点だけPL-02に置く。
3. 人物の信念が変わる点だけPL-04に置く。
4. 読者への情報操作をPL-05に置く。
5. 主人公の認識変化をPL-06に置く。
6. アンチテーゼ、暫定回答、誤答、最終回答、定着など、価値判断が変わる地点をPL-07に置く。

### Phase 6：点検

1. Outlineで表の事件だけを読み、因果を確認する。
2. PL-02だけを見て、貫通行動の停滞を確認する。
3. PL-05だけを見て、伏線の間隔と回収を確認する。
4. PL-06だけを見て、主人公が不自然に察していないか確認する。
5. PL-07だけを見て、各話が同じ主張を繰り返していないか確認する。

## 18. AIとの協働規則

AIは次の手順を守る。

1. 確定済み情報、仮置き、AI提案を区別する。
2. 提案対象を固定IDで示す。
3. 変更前、変更案、理由、波及箇所を明記する。
4. 採用されていない提案を、確定設定として後続回答に混ぜない。
5. 大きな変更では、少なくとも保守案・中間案・大胆案を比較する。
6. 伏線を増やす提案では、回収位置も同時に提案する。
7. Episodeの局所的満足と、全体への寄与を別々に評価する。
8. 真相を変更する場合は、既存の全伏線への影響を列挙する。
9. 文体案と構造案を混同しない。
10. ユーザーの承認後にだけ、修正版の正本を作る。
11. 全体幕の判定では第4節を優先し、「大きな転換点」「最低点」「真相開示」を自動的に全体幕`転`へ分類しない。
12. 起承転結を診断するときは、各幕について「現在の所属」「実際に果たしている機能」「不足している記述」を分けて示す。
13. 転でテーマが選択と行動として伝わり、結が定着と余韻に限定されているかを必ず点検する。
