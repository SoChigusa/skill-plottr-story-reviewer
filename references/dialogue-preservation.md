# セリフ保存・復元

## 原則

セリフ、内言、掛け合いは作者が蓄えた執筆素材として扱う。原文の言い回しをそのまま残し、改訂後の因果へ配置する。ストーリー上の必要性だけで保存対象を選ばず、人物らしさや余白を担う一言も保つ。

## 読み比べる三つのファイル

1. 作者が渡した原本：保存すべきセリフの基準。
2. 直前の改訂版：今回の変更範囲の基準。
3. 復元後の比較版：今回の成果物。

原本から二世代以上経った比較版を直すときも、原本まで戻って照合する。直前版だけを基準にすると、以前消えたセリフを検出できない。

## 復元手順

- 元カードIDとScene IDから対応を取り、括弧付きのセリフ、内言、括弧のない会話、語調を担う短いやり取りを読む。
- 各行について、話者、対象、発言時刻、知識、現在の場面への適合を確認する。
- 両立する行を原文のまま同じ場面へ戻す。要約だけ残った箇所には、元の会話を置く。
- 配置だけが合わない行は、同じ人物が同じことを言える位置へ移す。移動先と理由を報告する。
- 発言時刻や合図の条件などが変わった行は、必要な語句だけ調整し、原文と改稿文を併記する。
- 解決に構造変更や作者の選択が必要な行は、外部の保留一覧へ原文を保存する。元案の却下とは扱わない。
- 原文の誤字らしい箇所、未確定名、複数の代案も残す。誤字修正は依頼がある場合に別差分へ分ける。

## 文章の整え方

地の文は、誰が何を知り、どう動くかが分かる分量にする。セリフを戻すための短い接続に留め、別の性格、能力、動機、事件を追加しない。

セリフが含む否定、誇張、推測、皮肉は、人物の認識として読む。事実の検証コメントとは別に扱う。人物が知らないことを知っているように見える場合は、誤解・推測として既存の根拠があるか確認する。

## 機械照合

```bash
python scripts/audit_plottr_dialogue.py author.pltr restored.pltr \
  --baseline previous.pltr --decisions dialogue-decisions.json \
  --json-out dialogue-audit.json --markdown dialogue-audit.md
```

`--cards 73 74 75` のように原本のカードIDへ範囲を絞れる。`--line PL-01` が既定。別のPlotlineの文章を編集するときは、その線でも同じ検査を行う。

判定ファイルは引用IDをキーにする。IDは `D-カードID-引用順`。例：

```json
{
  "D-073-002": {
    "status": "moved",
    "target_card": 74,
    "reason": "発言者を維持し、本人が事実を知った後の場面へ移した。"
  },
  "D-073-003": {
    "status": "adapted",
    "target_card": 73,
    "replacement": "「二つ目の合図を待って」",
    "reason": "改訂後の発動条件に合わせた。"
  },
  "D-073-004": {
    "status": "held",
    "reason": "別案の能力設定を前提とするため、原文を保留一覧へ保存した。"
  }
}
```

引用抽出は候補の一覧である。文書の引用、見出し、キーワードは `non_dialogue` と理由を付けて区別する。引用符のないセリフや内言も手作業で確認する。全文内に同じ文字列があっても、話者や時系列が違えば保存済みとは判定しない。

## 出力前の確認

全候補に扱いが付いていること、復元・移動とした原文が実際に出力ファイルへ残っていること、調整とした改稿文が存在することを検証する。対象外のフィールドとオブジェクトは直前版と比較し、無関係な差分を戻す。
